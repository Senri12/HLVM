# Lab 4: Erlang application calling SimpleLang/JVM functions

This directory contains the task 4 demonstration for variant 8, Erlang.

The application is intentionally split into three layers:

- `src/lab4_math.sl` contains functions written in SimpleLang.
- `SimpleLangProgram.class` is generated by the existing JVM backend.
- Erlang starts a Java port process and calls the generated static methods through `SlBridge`.

## Build

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_lab4_erlang.ps1
```

The build uses the existing `tools/remote-parser.ps1` pipeline, so the remote parser service must be available on the configured host and port.

## Run demo

```powershell
erl -pa build/lab4_app -noshell -s lab4_app demo -s init stop
```

## Run interactive console

```powershell
erl -pa build/lab4_app -noshell -s lab4_app main -s init stop
```

The bridge protocol is line based:

```text
call gcd 48 18
ok 6
```

`sl_port:call/2` accepts these Erlang argument forms:

- integers, floats, booleans: `42`, `3.14`, `true`
- strings: `{string, "text"}`
- characters: `{char, $A}`
- one-dimensional arrays: `{array, [1, 2, 3]}`

The current JVM backend emits SimpleLang scalar values as JVM `int`, except `void`.
The bridge is broader than that on purpose: if the generated class exposes JVM
`boolean`, `byte`, `short`, `long`, `char`, `float`, `double`, `String`, or
one-dimensional arrays, the same Erlang port layer can call them.

This keeps the FFI boundary visible for the report and avoids linking unsafe native code into BEAM.

If a custom build directory is used, set `LAB4_CLASSPATH` to that directory before starting Erlang.
